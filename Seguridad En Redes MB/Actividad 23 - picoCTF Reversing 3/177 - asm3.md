# DESCRIPCIÓN:
**asm3** — Reverse Engineering (Hard) — by Sanjay C · picoCTF 2019

What does `asm3(0xc682a0b0,0xf2b059d1,0xccc1df85)` return? Submit la respuesta como valor hexadecimal (empieza con '0x'). Ojo: aquí tampoco va en formato `picoCTF{...}`. [Source](https://challenge-files.cylabacademy.net/library/9c1d403a72b67a2f8ea1eaec314c81ec2ee7b35b74e25a9d48718b9f5dfdc8a2/test.S)

**Hint:** [registros](https://wiki.skullsecurity.org/index.php?title=Registers) — aquí ya no solo usan `eax`, sino también `ax`, `ah` y `al` (los pedazos de 16 y 8 bits del mismo registro).

# SOLUCIÓN:
#### 0x1dcf

```
xor eax,eax
mov ah, [ebp+0xa]
shl ax, 0x10
sub al, [ebp+0xf]
add ah, [ebp+0xc]
xor ax, WORD PTR [ebp+0x12]
```

La función recibe 3 parámetros de 4 bytes, acomodados en el stack uno tras otro: `a` en `[ebp+0x8..0xb]`, `b` en `[ebp+0xc..0xf]`, `c` en `[ebp+0x10..0x13]`. Como todo está en little-endian, cada parámetro queda "al revés" en memoria (el byte menos significativo primero). Entonces desglosé los 3 parámetros en sus bytes:

- `a = 0xc682a0b0` → bytes en memoria: `[+8]=b0  [+9]=a0  [+a]=82  [+b]=c6`
- `b = 0xf2b059d1` → bytes en memoria: `[+c]=d1  [+d]=59  [+e]=b0  [+f]=f2`
- `c = 0xccc1df85` → bytes en memoria: `[+10]=85  [+11]=df  [+12]=c1  [+13]=cc`

Con eso, seguí el código paso a paso:

1. `xor eax,eax` → `eax = 0`.
2. `mov ah,[ebp+0xa]` → agarra el byte `0x82` de `a` y lo mete en `ah` → `ax = 0x8200`.
3. `shl ax,0x10` → acá está el truco: intenta desplazar 16 bits a un registro que solo tiene 16 bits, así que se queda en puro `0` (todos los bits se le salen). → `ax = 0x0000`.
4. `sub al,[ebp+0xf]` → `al = 0x00 - 0xf2`. Como es resta de 8 bits con swap (sin signo), da `0x0e` (pide prestado / wrap-around: `0x100 - 0xf2 = 0x0e`).
5. `add ah,[ebp+0xc]` → `ah = 0x00 + 0xd1 = 0xd1`. Ahora `ax = 0xd10e`.
6. `xor ax, WORD PTR [ebp+0x12]` → ese word junta los bytes `[+12]=c1` y `[+13]=cc` → `0xccc1`. Entonces `ax = 0xd10e XOR 0xccc1 = 0x1dcf`.

Como `eax` arrancó en 0 y solo se tocó la mitad baja (`ax`), lo que regresa la función es `0x1dcf`.

# NOTAS ADICIONALES:
El paso que más se presta a confusión es el `shl ax,0x10`: aunque `0x10` normalmente es válido para desplazar un registro de 32 bits, aquí el destino es de 16 bits (`ax`), así que el resultado se vacía por completo a `0`. Si no caes en cuenta de eso, el resultado final te va a salir mal.
