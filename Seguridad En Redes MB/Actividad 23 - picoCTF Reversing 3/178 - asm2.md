# DESCRIPCIÓN:
**asm2** — Reverse Engineering (Medium) — by Sanjay C · picoCTF 2019

What does `asm2(0x4,0x29)` return? Submit la respuesta como valor hexadecimal (empieza con '0x'). Tampoco va en formato `picoCTF{...}`. [Source](https://challenge-files.cylabacademy.net/library/970db6f9114bc04f46705c691cb4b3c3f2a9631904e972a84e9ce8d29714d3c8/test.S)

# SOLUCIÓN:
#### 0x8c

```
local_4 = param2        ; [ebp-0x4] = [ebp+0xc]
local_8 = param1        ; [ebp-0x8] = [ebp+0x8]
jmp check
body:
  local_4 += 1
  local_8 += 0x94
check:
  if (local_8 <= 0x38f0) goto body
return local_4
```

Esta ya no es puro salto condicional, es un loop disfrazado de assembly: agarra `local_8` (que arranca en el primer parámetro) y le va sumando `0x94` cada vuelta, mientras no se pase de `0x38f0`. Cada vuelta que entra, también le suma 1 a `local_4` (que arranca en el segundo parámetro, y es lo que al final regresa la función).

Con `asm2(0x4, 0x29)`:
- `local_8` arranca en `0x4` y `local_4` en `0x29` (41 en decimal).
- `local_8` va avanzando de 148 en 148 (`0x94 = 148`) mientras siga `<= 0x38f0` (14576 en decimal).
- Fui contando cuántas veces cabe sumar 148 a partir de 4 sin pasarse de 14576: `(14576 - 4) / 148 = 98.46...`, como el loop checa *antes* de salir, en realidad entran **99 vueltas** completas.
- Entonces `local_4 = 41 + 99 = 140`.

`140` en hex es `0x8c`.

# NOTAS ADICIONALES:
El truco acá es que el `jmp` al inicio manda directo al `cmp` (osea primero checa la condición, no ejecuta el cuerpo "a ciegas"), así que es un `while` normal y no un `do-while` — importa para no pasarte de vueltas al contar.
